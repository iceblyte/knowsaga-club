# Spec Delta

> 强度词约定：`（MUST）` = 硬性约束，接口 / 行为必须遵守，不满足即视为未实现；
> `（MUST NOT）` = 硬性禁止；`（SHOULD）` = 建议项，允许有理由的例外。
> 每个 Requirement 只在该条**承担强制语义**的位置标注，未标注的句子属于对约束的解释或背景。

## Purpose

约束「生成出来的学习内容以什么为事实依据」。这一层直接对应产品最核心的承诺：
用户答的每一道题、读的每一段讲解，都必须是可信的知识，而不是模型的猜测。

本能力是新增的。`openspec/specs/` 此前为空，故本文件即该能力的基线要求。

## ADDED Requirements

### Requirement: 有资料时，题目必须以资料为唯一事实依据

当出题获得了外部取材资料时，题干、选项、正确答案与讲解的内容必须（MUST）能在资料中找到依据；
模型自身的记忆与资料冲突时，**以资料为准**。

#### Scenario: 资料覆盖了该概念的权威口径
- **WHEN** 资料中给出了某概念的定义、组成部分或适用边界
- **THEN** 题目与讲解按资料的口径表述，不出现资料中不存在的具体数据、时间、版本号或结论

#### Scenario: 模型记忆与资料冲突
- **WHEN** 资料对某事实的表述与模型自身记忆不一致
- **THEN** 采用资料的表述

#### Scenario: 检索到的资料与学习需求无关
- **WHEN** 检索命中了内容，但资料与该次学习需求所指的概念无关
- **THEN** 这批资料被**忽略**，出题按「没有资料」的情形处理 —— 宁可不使用资料，也不把无关内容强行套进题目

#### Scenario: 用户自己给出的资料不适用「无关即忽略」
- **WHEN** 资料来自用户输入里给出的网页链接
- **THEN** 不得以「与输入无关」为由忽略它 —— 用户给出的资料就是他要学的东西；
  忽略它等于回到「贴了链接却没被读」

### Requirement: 学习需求是一个网页链接时，学习范围由该页面内容确定

用户可能只粘贴一个网址，表达的是「我要学这个页面里的东西」。
此时系统必须（MUST）把该页面的内容当作学习范围的来源，而不是把网址字符串本身当作一个待解释的概念。

#### Scenario: 输入只有一个网址
- **WHEN** 用户输入只有一个网页链接、没有其他说明文字
- **THEN** 题目的考察内容围绕该页面的内容展开，不出现围绕「网址字符串」本身的题

#### Scenario: 输入是网址加一句说明
- **WHEN** 用户输入是「<网址> 帮我学一下这个」这类形式
- **THEN** 以页面内容为学习范围，说明文字作为侧重点的提示，不把说明文字当作一个独立的学习主题

#### Scenario: 页面内容与模型记忆冲突
- **WHEN** 该页面的表述与模型自身记忆不一致
- **THEN** 以页面内容为准（该页面是用户指定的来源）

### Requirement: 没有资料时，不得用「别处的知识」冒充用户要学的概念

这是本次改动要解决的核心问题：用户想学一个模型训练数据之外的新概念时，模型会拿**其他领域的
同名或近名知识**凑出一道题，而题面看不出任何异常。系统必须（MUST）约束这种替换行为 ——
不得（MUST NOT）改用其他领域的同名/近名概念来出题，也不得（MUST NOT）为了凑题而编造事实或离开该概念去写别的主题。

其中「换用不依赖不确定事实的考察角度」属于实践建议（SHOULD）：它是达成上述禁止项的首选手法，但不是唯一手法。

#### Scenario: 用户输入的是一个模型不熟悉的新概念
- **WHEN** 没有可用资料，且用户输入的概念不在模型的可靠知识范围内
- **THEN** 不得改用其他领域的同名/近名概念来出题；题目必须仍然围绕用户输入字面所指的概念

#### Scenario: 把握不足时的取舍
- **WHEN** 某个考察角度需要模型不确定的具体事实（版本号、发布日期、人名、机构名、数字）
- **THEN** 换用不依赖这些具体事实的考察角度（如概念命名、适用边界、与相邻概念的区别），
  而不是把不确定的内容写成确定的答案

#### Scenario: 题量下限不通过编造来满足
- **WHEN** 用户输入很短或概念很新，围绕它可出的稳妥题目有限
- **THEN** 通过补充考察角度凑足题量下限，**不得**为了凑题而编造事实，也不得离开该概念去写别的主题

#### Scenario: 生成不出合格题目时如实报错
- **WHEN** 所有尝试都无法产出符合质量闸门的题目
- **THEN** 以「出题失败，请重试」结束本次召唤，**不得**返回一份内容可疑但结构合法的题库来充当成功

### Requirement: 复盘报告不得引入题库之外的知识

报告是对本次答题情况的复述。它的掌握点、薄弱点与知识总结应（SHOULD）限定在本次题库已考到的范围内，
不补充题库里没有出现过的事实或知识点 —— 这一层由 Prompt 约束、无法被程序完全验证，故不标为绝对强制。

但报告链的**输入**必须（MUST）是已被资料约束过的题库本身：不得（MUST NOT）把第三方页面原文
再次注入报告生成，也不得（MUST NOT）在重新生成报告时重新取材或换用新资料。

#### Scenario: 三句话知识总结
- **WHEN** 生成复盘报告的三句话知识总结
- **THEN** 每一句都能在本次题库的题干、选项或讲解中找到出处，不引入题库之外的新知识

#### Scenario: 掌握点与薄弱点
- **WHEN** 生成掌握点与薄弱点
- **THEN** 只取本次题库中出现过的知识点标签，全部答对时薄弱点为空数组，不为凑数编造

#### Scenario: 报告不直接使用第三方原文
- **WHEN** 生成复盘报告
- **THEN** 报告链的输入是已被资料约束过的题库本身，不把第三方页面原文再次注入报告生成

#### Scenario: 报告复用同一份依据
- **WHEN** 用户对同一次挑战重新生成报告
- **THEN** 报告依据的仍是该次题库所对应的那份资料快照，不重新取材、也不换用新资料
