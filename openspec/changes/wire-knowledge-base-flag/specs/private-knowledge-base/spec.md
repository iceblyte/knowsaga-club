# Spec Delta

## ADDED Requirements

### Requirement: 功能开关决定这条路可不可见，它不是权限位

部署必须（MUST）能用一个开关整体声明「本部署不提供私有知识库」。该开关关闭时，
系统必须（MUST）不把知识库检索作为取材工具交给模型，前端必须（MUST）不展示任何通往知识库的入口，
并且文案不得（MUST NOT）承诺该部署并不提供的能力（例如「可以把文档收进知识库」）。

该开关**不得**（MUST NOT）被当作访问控制：知识库的接口仍必须（MUST）可用，
其访问控制由登录态与归属校验承担。开关关闭**不等于**接口关闭。

#### Scenario: 开关关闭时模型拿不到知识库工具
- **WHEN** 该开关关闭，而用户仍然带了一个知识库标识发来召唤请求
- **THEN** 取材链不提供知识库检索工具，模型一次知识库检索也发不出来；
  召唤本身照常进行（按「本次没有资料」处理），不因此失败

#### Scenario: 开关关闭时用户看不到入口
- **WHEN** 该开关关闭，用户在客户端浏览
- **THEN** 通往知识库的入口都不出现（大厅的资料入口、个人页与工坊页的知识库行），
  且页面上不出现「可以上传文档建库」这类承诺

#### Scenario: 开关关闭不等于接口关闭
- **WHEN** 该开关关闭，但请求直接调用了知识库接口
- **THEN** 接口仍按既有规则响应（受登录态与归属校验约束），
  不因为开关关闭而返回「找不到」——那会与「路径写错了」长得一模一样

#### Scenario: 开关打开时与没有这个开关时一致
- **WHEN** 该开关打开
- **THEN** 入口与取材能力都正常提供，界面与链路不出现任何因本开关带来的额外差异

### Requirement: 开关值必须由后端下发给前端

为避免前后端各配一份而漂移，前端判断入口显隐所需的开关值必须（MUST）由后端下发；
前端不得（MUST NOT）自行维护一份开关常量。取不到该值时，前端**应当**（SHOULD）按「关闭」处理 ——
宁可少显示一个入口，也不让用户点进一条走不通的路。

#### Scenario: 前端拿到开关值
- **WHEN** 客户端启动并成功探测到后端
- **THEN** 它按后端下发的值决定入口显隐，不依据自身配置或本地缓存推断

#### Scenario: 探测不到开关值
- **WHEN** 前端没有取到该值（后端未启动、探测失败）
- **THEN** 入口按不显示处理，不出现「看得见但点不通」的死入口
