# Spec Delta

## ADDED Requirements

### Requirement: 配图必须由服务端生成、转存并随题目一并下发（MUST）

用户勾选「生成配图」时，系统必须（MUST）为每道题生成一张与题目内容相关的图片，
并把它转存到产品自己的对象存储上、以**长期有效**的地址随题目一并下发给客户端。
不得（MUST NOT）把上游生图接口返回的临时地址直接当作配图地址下发 —— 该地址
有效期只有 24 小时，而题目是永久保存的：过期后用户回看历史卷轴只会看到一片裂图，
且没有任何提示。客户端不得（MUST NOT）为取图再发起第二次请求。

#### Scenario: 勾选后每道题都拿到配图
- **WHEN** 用户勾选「生成配图」并发起召唤，且生图与转存都成功
- **THEN** 出题结果里每道题都带一个图片地址，该地址不依赖上游的临时链接、长期可访问

#### Scenario: 不勾选时链路无变化
- **WHEN** 用户没有勾选「生成配图」
- **THEN** 题目都不带图片地址，并且**不发生任何生图或转存调用**，出题耗时与接入本能力之前一致

#### Scenario: 历史回看仍然能看到图
- **WHEN** 用户隔天在历史卷轴详情里回看这次挑战
- **THEN** 配图仍然显示得出来（地址不是 24 小时就失效的临时链接）

### Requirement: 配图不得泄露选项内容与正确答案（MUST NOT）

生图提示词必须（MUST）只依据知识点与题干主题构成。不得（MUST NOT）把选项文字或
正确答案写进提示词，也不得（MUST NOT）让画面中出现文字。理由：「下面哪个是苹果」
这类题一旦把答案物件画进画面，配图就等于泄题，而配图是**永久**留在题目里的，
比一次性的提示更难收回。

#### Scenario: 选择题的配图不包含答案
- **WHEN** 一道选择题（正确答案是某个具体物件）生成了配图
- **THEN** 画面里不出现那个正确答案物件，也不出现任何选项文字、题面文字或其它文字

#### Scenario: 提示词不引入题干之外的事实
- **WHEN** 构建生图提示词
- **THEN** 只用知识点标签与从题干取得的主题词，不把选项、答案或外部新知识写进去

### Requirement: 生图失败不得影响出题（MUST）

生图是出题的**增强项**。任何一环失败（上游报错 / 超时 / 转存失败 / 额度不足）
都必须（MUST）只让对应的题目没有配图；本次出题必须（MUST）照常成功返回题目。
不得（MUST NOT）因为配图没生成出来而把整个出题任务判为失败，也不得（MUST NOT）
把「一张图都没有」包装成配图已生成。

#### Scenario: 上游全部失败
- **WHEN** 生图调用全部失败
- **THEN** 任务照常成功、题目全部正常下发，只是都不带图片

#### Scenario: 部分成功
- **WHEN** 一次 5 道题的召唤里有 2 张生图失败
- **THEN** 失败的那 2 道不带图片、其余 3 道正常带图，用户不会为此看到错误提示

#### Scenario: 生图拖慢整体
- **WHEN** 生图耗时逼近该段的时间预算
- **THEN** 放弃剩余未生成的图并直接收尾，不让整次召唤被图片拖成超时

#### Scenario: 如实反映生成情况
- **WHEN** 用户勾选了配图但没有得到全部图片
- **THEN** 界面**不**宣称「配图已生成」，配图进度相关文案如实反映实际结果

### Requirement: 按人按天的生图额度（MUST）

系统必须（MUST）限制单个用户每天可以生成多少张图（默认 20 张），
且该判定必须（MUST）发生在**创建出题任务之前**。额度不足时必须（MUST）
拒绝这次带配图的召唤，并用一句面向用户的提示说明「关掉配图即可继续」。
消耗必须（MUST）只计入**真正生成成功**的张数；「今天」必须（MUST）按产品的业务时区判定。

#### Scenario: 额度不足时提前拒绝
- **WHEN** 用户当天剩余额度不足以覆盖本次题量，且他勾选了配图
- **THEN** 请求被拒绝并给出友好提示（说明关掉配图就能继续），**不创建**一个注定缺图的任务

#### Scenario: 失败与取消不消耗额度
- **WHEN** 一次带配图的召唤中部分图片生成失败，或整次任务在出题阶段就失败 / 被用户取消
- **THEN** 只有真正生成并转存成功的张数计入当天消耗，其余退还

#### Scenario: 跨天重置
- **WHEN** 用户昨天已用满额度，今天再次发起带配图的召唤
- **THEN** 按今天的额度重新计算（边界是业务时区的自然日，不是 UTC 日）

### Requirement: 配图能力不可用时不得给出入口（MUST）

该能力由一个部署级开关控制，默认关闭。开关关闭、或生图所依赖的凭据不齐全时，
系统必须（MUST）不向客户端提供「生成配图」入口，并且必须（MUST）拒绝客户端
自行传来的开启请求、如实告知该部署未提供此能力。开关值必须（MUST）由后端下发，
前端不得（MUST NOT）自行维护一份开关常量。

#### Scenario: 部署未启用
- **WHEN** 部署没有开启配图能力
- **THEN** 界面上不出现「生成配图」入口；客户端伪造该参数也会被后端以友好提示拒绝

#### Scenario: 开关打开但凭据不全
- **WHEN** 开关打开，但生图或对象存储的凭据没有配全
- **THEN** 该能力对外仍表现为「未启用」（不给入口），而不是表现为「点了必然报错」

#### Scenario: 开关打开时正常可用
- **WHEN** 开关打开且凭据齐备
- **THEN** 入口正常出现，用户可以勾选并把配图带回家

### Requirement: 配图必须与出题同批就绪，且等待过程可见（SHOULD）

配图应当（SHOULD）在本次出题的同一次任务里完成，不需要用户额外操作、
也不需要第二次等待；等待过程中应当（SHOULD）让用户看见配图正在进行。这一层是
体验要求 —— 即便某次配图被跳过，题目本身仍然可用，所以不标为绝对强制。

#### Scenario: 等待过程可见
- **WHEN** 用户勾选配图后停留在等待界面
- **THEN** 出题这一步的说明文字里能看到配图的进行情况，而不是一个十几秒不动的「正在生成」

#### Scenario: 不新增步骤
- **WHEN** 展示等待进度
- **THEN** 仍是既有的步骤结构（取材 → 出题 → 校验），配图的进度并入「出题」这一步
