# ui-theme Specification

> 强度词约定：`（MUST）` = 硬性约束，接口 / 行为必须遵守，不满足即视为未实现；
> `（MUST NOT）` = 硬性禁止；`（SHOULD）` = 建议项，允许有理由的例外。
> 每个 Requirement 只在该条**承担强制语义**的位置标注，未标注的句子属于对约束的解释或背景。

## Purpose

`ui-theme` 定义「界面主题」这一能力的行为契约：一套预置主题的取值集合、选中结果的持久化与跨设备一致、
切换后的生效范围、读不清时的降级，以及换肤覆盖不到的部分如何如实呈现。
它只改变**颜色的来源**，不改变任何页面的结构、文案、尺寸、圆角与交互。

本文件是该能力的基线要求。

## Requirements

### Requirement: 主题取值必须来自预置集合，未设置时为默认主题（MUST）

系统必须（MUST）只接受下列五个主题标识：`paper`（纸与印）、`indigo`（宣纸靛墨）、
`vermilion`（素白墨朱）、`midnight`（夜航公会）、`lime`（青柠）。用户从未做过选择时，
其主题必须（MUST）是 `paper`。

#### Scenario: 老用户升级后主题为默认

- **WHEN** 一个从未选择过主题的老用户登录
- **THEN** 其主题是 `paper`，且界面的颜色与本次接入之前完全一致

#### Scenario: 合法主题被接受

- **WHEN** 客户端提交集合里的任一标识
- **THEN** 该值被保存，并作为后续读取的返回值原样返回

### Requirement: 非法主题必须被拒绝，不得静默兜底（MUST）

客户端提交集合之外的值时，服务端必须（MUST）拒绝该请求并返回可识别的错误，
不得（MUST NOT）静默落库、也不得（MUST NOT）静默改写成默认值 —— 这个值决定客户端
加载哪一套皮肤，静默兜底会把「前端哪里写错了」掩盖成「看起来正常」。

#### Scenario: 非法主题被拒绝

- **WHEN** 客户端提交一个不在预置集合里的主题标识
- **THEN** 请求被拒绝并返回明确错误，该用户已保存的主题保持不变

### Requirement: 主题是用户级偏好，必须持久化且跨设备一致（MUST）

主题选择必须（MUST）保存在服务端、与该用户绑定，而不是只留在本机：换设备或重装后
登录同一账号，必须（MUST）拿到同一套主题。客户端提供的「清理缓存」必须（MUST NOT）
把主题清回默认 —— 它是用户偏好，不是可丢弃的缓存。不同用户之间必须（MUST）互不影响。

#### Scenario: 换设备后主题跟随

- **WHEN** 用户在一台设备上选择了某套主题，随后在另一台设备登录同一账号
- **THEN** 新设备呈现的是同一套主题

#### Scenario: 清理缓存不重置主题

- **WHEN** 用户执行客户端提供的「清理缓存」
- **THEN** 主题保持为用户已选择的那一套，不回到默认

#### Scenario: 用户之间互不影响

- **WHEN** 另一个用户读取自己的设置
- **THEN** 拿到的是他自己的主题，不受前一个用户选择的影响

### Requirement: 默认主题下界面必须零视觉漂移（MUST）

在默认主题（`paper`）下，所有页面的外观必须（MUST）与接入本能力之前逐项一致：
颜色、尺寸、圆角、阴影与字距都不得（MUST NOT）发生变化。理由：这是对既有设计的一次
基础设施改造，允许它改变默认外观就等于放行一次无人审核的全站改版。

#### Scenario: 逐令牌比对无差异

- **WHEN** 在同一屏上对比改造前后默认主题的计算样式
- **THEN** 每一个颜色令牌的取值都与改造前相同

#### Scenario: 不作选择时永不出现其它主题的色

- **WHEN** 用户从未选择主题，浏览大厅 / 答题 / 冒险日志 / 我的四个页面
- **THEN** 这四个页面都不出现任何新增主题的色值

### Requirement: 切换主题必须即时生效并覆盖全站（MUST）

用户选定一套主题后，界面必须（MUST）立即采用新配色，不需要重启应用或重新进入页面；
除下一条登记的例外之外，所有页面与底部标签栏都必须（MUST）采用新配色。

#### Scenario: 切换后回到其它页面仍是新主题

- **WHEN** 用户在选择页选定一套主题，随后返回社团大厅
- **THEN** 大厅以该主题的配色呈现，底部标签栏同样采用该主题

#### Scenario: 标签栏图标的像素色随之切换

- **WHEN** 切换到任一非默认主题后查看底部标签栏
- **THEN** 未选中与选中图标的**像素色**分别等于该主题的未选中色与选中色令牌，
  而不是默认主题那一套图标 —— 图标是位图，它的颜色无法由 CSS 变量改写，
  所以必须按主题各备一套并在切换时取用

#### Scenario: 再次进入子页仍保持

- **WHEN** 用户切换主题后进入任意答题页或冒险日志页
- **THEN** 该页面同样采用选中的主题，而不是回退到默认

### Requirement: 保存失败必须恢复到切换前的主题（MUST）

把选择保存到服务端失败时，界面必须（MUST）恢复成切换前的主题，并让用户知道本次切换没有生效。
不得（MUST NOT）让界面停留在服务端并未保存的那一套主题上 —— 否则用户下次进入会看到
界面自己变了，却没有任何解释。

#### Scenario: 保存失败时翻回

- **WHEN** 用户选定一套新主题，而保存请求失败
- **THEN** 界面回到切换前的主题，并给出提示说明本次切换未生效

### Requirement: 每套主题的文字必须保持可读（MUST）

每套预置主题下，正文与标题文字相对其所在背景的对比度必须（MUST）达到 WCAG AA
（正文 4.5:1、大字 3:1）；用于表达状态的色（正确 / 错误 / 选中）相对背景也必须（MUST）
满足非文本对比度 3:1。不得（MUST NOT）为了观感把文字或状态色压到读不清的对比度上。

#### Scenario: 五套主题的语义色对全部达标

- **WHEN** 逐套核算五套主题里正文、次级文字、状态色相对各自背景的对比度
- **THEN** 全部达到 AA 门槛，且没有只差零点几的压线项

### Requirement: 换肤覆盖不到的部分不得被宣称已覆盖（MUST NOT）

微信原生的弹窗与轻提示、以及由脚本绘制的导出图与图形，都不受主题影响。
面向用户的文案与交付说明不得（MUST NOT）宣称「全部界面元素都会随主题变化」，
也不得（MUST NOT）把这些固定色描述成某种主题色。

#### Scenario: 原生弹窗不随主题且如实说明

- **WHEN** 用户切换到暗色主题并触发一个微信原生弹窗
- **THEN** 弹窗保持系统配色（这是机制决定的边界，不是缺陷），且面向用户的边界说明中已写明这一点

#### Scenario: 边界说明里不得残留已被推翻的旧边界

- **WHEN** 检查面向用户的边界说明（如设置页的主题说明文案）
- **THEN** 其中不得再出现「底部标签栏图标不随主题变化」这类**实现已经做不到**的旧声明 ——
  过度声明边界与过度声明能力一样是失真
