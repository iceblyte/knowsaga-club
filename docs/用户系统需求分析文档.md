## 1. 需求背景

### 1.1 现状（代码实测，非推测）

| 现状 | 实测证据 |
|---|---|
| 后端只有 `health` / `quiz.generate` / `tasks.*` 三类接口 | `backend/app/api/v1/routes/` 仅 3 个模块 |
| **零持久化** | 任务表为进程内内存 + TTL，进程重启即归零；仓库内无任何数据库依赖 |
| **零用户概念** | 全仓 grep `openid` / `jwt` / `Authorization` / `token`，除 LLM 的 token 计数外**零命中** |
| 出题与答题不带用户身份 | `models/quiz.py`、`task_service.py` 中无 `user_id` |
| 结算在前端本地完成 | `frontend/src/utils/scoring.ts` |
| `pages/mine`、`pages/report` 是占位页 | 两处均为 ComingSoon |

**结论**：项目此前**没有用户系统的任何一行代码**。所以本次不是「改造已有登录」而是**从零新建**——这也意味着本文档要对登录态、鉴权、数据归属一次性定死口径，避免边做边改。

### 1.2 本次要解决的四个问题

1. **无身份**：无法区分两个用户，无法回答「这是谁的数据」。
2. **无留存**：关掉进程数据全丢，用户学完一局什么都留不下。
3. **无复盘**：需求文档 §3 的 P1「后台错题与分析复盘」、原型 04 的 9 屏，全部无数据可支撑。
4. **数据不可信**：结算在前端算，服务端只能「用户报什么就是什么」，档案里的每个数字都没有权威来源。

### 1.3 目标（可度量）

| # | 目标 | 度量方式 |
|---|---|---|
| G1 | 用户全程无感知地获得稳定身份 | 首次进入 3 秒内完成登录建档；**不出现任何授权弹窗**（头像昵称页除外，且仅在该页） |
| G2 | 一局挑战的数据完整落库 | 结束一局后，卷轴/题目/作答/报告四项均可从服务端重新读出 |
| G3 | 档案数据唯一权威 | 原型 04 的 9 屏所有数字均来自服务端接口，无本地演示常量 |
| G4 | 复盘闭环可用 | 报告 → 历史卷轴 → 卷轴详情 → 重新挑战，四步连续可走通 |
| G5 | 数据不串号 | 任何用户不可能读到、改到他人的卷轴/作答/报告 |

> **非目标**：不做高并发、不做多端登录管理、不做账号密码体系、不做好友/排行榜/对战。

## 2. 用户与场景

### 2.1 用户画像

典型用户：用微信打开小程序、想用碎片时间「把一段资料学成关卡」的单个学习者。特征：
- **零耐心**：多一个授权弹窗、多一步填写，流失概率显著上升。
- **看结果**：判断产品好坏看两件事——「题出得准不准」「我到底进步了多少」。
- **会回来**：如果「上次错的题今天该重做」这件事被提醒到，回访意愿高。

**设计要求**：身份建立必须完全静默；成长反馈必须来自真实数据；回访钩子必须具体到「哪几道题、几分钟」。

### 2.2 核心场景

#### S1 首次进入（静默登录 + 自动建档）
1. 用户点开小程序 → 进入启动页。
2. 系统在后台取一个临时登录凭证，交给服务端换取用户身份。
3. 服务端发现是新用户 → 自动建档（默认昵称「冒险者 · XXXX」、默认头像、等级 1、0 XP）。
4. 用户在完全无感知的情况下进入社团大厅，可以直接开始输入资料。

> 全程无弹窗、无按钮、无需用户做任何选择。这是本需求最硬的一条。

#### S2 日常闯关（出题 → 答题 → 结算）
1. 在大厅输入一句话/一段文本 → 召唤副本（异步生成，进度条三步）。
2. 生成完成后进入题库确认页 → 开始答题。
3. 逐题作答，答对答错即时反馈 + 讲解（这一环节的即时性不因本次改造而降低）。
4. 答完交卷 → **由服务端判定并计分** → 结算页展示服务端结果（XP、金币、正确率、击败百分比）。
5. 后台同时：写入作答明细、更新累计 XP/等级/连续天数、错题入队、更新知识领域掌握度、检查勋章解锁。

#### S3 复盘（报告 → 历史卷轴 → 卷轴详情）
1. 结算页点「查看冒险日志」→ 进入报告页，报告为异步生成（三步进度）。
2. 报告就绪 → 看到正确率、三句话总结、掌握较好的/薄弱的知识点、三条建议。
3. 从个人中心进入「历史卷轴」，按时间倒序列出全部记录。
4. 点进任一条 → 卷轴详情，逐题回看当时的作答与讲解。
5. 可「重新挑战这一卷」或删除该条记录。

> 若报告生成失败：**答题记录必须完整保留**，用户可重新生成报告，而不是整局作废。

#### S4 回访（错题到期 → 提醒 → 复习关卡）
1. 用户下次进入小程序时，若今日有到期错题，在社团大厅与个人中心出现入口提示。
2. 点入复习提醒页：看到待复习题数、预计用时、可得 XP，以及「为什么是今天」的解释。
3. 点「开始重温」→ 用到期错题组一局复习关卡 → 答完同样走服务端结算。
4. 复习答对 → 该错题的复习阶段推进、下次到期时间推后；连续两次复习答对 → 移出错题队列。

#### S5 管理（设置 / 头像昵称 / 学习提醒）
1. 从「我的档案」右上角入口进入设置。
2. 修改头像与昵称（唯一需要用户主动授权的环节，仅在此页发生）。
3. 配置学习提醒的时间与星期、两个额外提醒开关，保存后**刷新仍保持**。
4. 查看帮助与反馈、举报题目问题、联系开发者。

## 3. 需求总览

| 层 | 名称 | 解决什么 | 需求组 |
|---|---|---|---|
| 1 | 身份与登录 | 是谁 | FR-A |
| 2 | 学习记录 | 学过什么（不可篡改） | FR-B |
| 3 | 成长与复盘 | 进步多少、哪里薄弱 | FR-C |
| 4 | 档案与设置 | 怎么看到、怎么调整 | FR-D |

**依赖关系（硬约束）**：FR-A 是全部需求的前置；FR-B 是 FR-C 与 FR-D 的前置。**没有 FR-B 就没有真实数据，FR-C/FR-D 只能造假**。因此实施顺序必须是 A → B →（C 与 D 并行）。

## 4. 功能需求详述

优先级：**P0** = 本轮必须完成；**P1** = 本轮完成，但可在 P0 稳定后接入。

### 4.1 第 1 层 · 身份与登录（FR-A）

| 编号 | 需求 | 说明 | 优先级 |
|---|---|---|---|
| FR-A1 | 静默登录 | 用户进入小程序即自动完成身份建立，无需任何点击或授权 | P0 |
| FR-A2 | 自动建档 | 首次出现的用户自动创建档案，无需注册流程 | P0 |
| FR-A3 | 登录态持有 | 登录态本地保存，后续所有请求自动携带 | P0 |
| FR-A4 | 失效静默恢复 | 登录态过期/失效时自动重新建立，用户无感；恢复失败才给出可理解的提示 | P0 |
| FR-A5 | 登出 | 用户主动登出后，旧登录态立即失效（不是只清本地） | P1 |
| FR-A6 | 开发调试通道 | 非微信环境下也能建立身份，用于本机联调；**生产环境该通道不存在** | P0 |
| FR-A7 | 隐私合规 | 涉及用户信息的环节满足小程序的隐私保护要求 | P0 |

**验收标准**

- FR-A1：全新用户从打开到进入大厅，无任何弹窗；重复进入不重复建档。
- FR-A2：新用户的昵称、头像、等级、XP 有合理默认值，个人中心可直接渲染。
- FR-A3：登录态在杀掉小程序后重新打开仍然有效，无需重新登录。
- FR-A4：人为把本地登录态改坏 → 下一次请求自动恢复并成功，用户无感知；若恢复也失败，落到启动页并给出「请重新进入」这类可理解提示（**界面不出现任何内部机制说明**）。
- FR-A5：登出后，用登出前的登录态再请求接口必须被拒绝。
- FR-A6：该通道仅在显式开启且为开发环境时可用；生产配置下请求该地址应返回「不存在」，而不是「无权限」。
- FR-A7：见 §6.1。

### 4.2 第 2 层 · 学习记录（FR-B）

| 编号 | 需求 | 说明 | 优先级 |
|---|---|---|---|
| FR-B1 | 卷轴与题目落库 | 生成成功的卷轴与题目持久保存，归属于用户 | P0 |
| FR-B2 | 服务端权威结算 | 交卷后由服务端重新判定、计分；前端只负责展示结果 | P0 |
| FR-B3 | 冒险日志生成与回看 | 报告异步生成、可失败、可重新生成；失败不影响答题记录 | P0 |
| FR-B4 | 历史卷轴与详情 | 列表按时间倒序 + 领域筛选；详情可逐题回看 | P1 |
| FR-B5 | 记录删除 | 支持删除单条历史记录；删除**仅移除记录，不影响整体统计** | P1 |
| FR-B6 | 数据归属校验 | 所有按 id 读取的接口必须校验归属，禁止横向越权 | P0 |
| FR-B7 | 重复提交防护 | 网络重试/连点不得产生重复的挑战记录 | P1 |

**验收标准**

- FR-B2：服务端计分结果与前端即时判定在**同一组用例**上完全一致（含多选题的四种分支：含错选、全对、非空真子集、空）；结算页展示的数字等于服务端返回值。
- FR-B3：报告生成中→成功，用户可看到报告；报告生成失败→答题记录仍在，历史卷轴里能看到这一局，且可重新生成。
- FR-B4：列表项 = 一次挑战（不是一份卷轴）；同一卷轴重做会产生多条记录，与原型 04·5「历史卷轴」的呈现一致。
- FR-B5：删除后该记录从列表消失，但累计 XP、正确率、等级**不变**。
- FR-B6：用 A 的登录态请求 B 的记录 → 被拒绝，且不泄漏该记录是否存在之外的任何内容。
- FR-B7：同一次交卷重复上报两次 → 只产生一条挑战记录。

### 4.3 第 3 层 · 成长与复盘（FR-C）

| 编号 | 需求 | 说明 | 优先级 |
|---|---|---|---|
| FR-C1 | 学习数据看板 | 近 7 天答题量柱状图、正确率趋势、平均单局用时、各知识领域掌握度 | P1 |
| FR-C2 | 知识树 | 按知识领域聚合掌握度，三态：未开始 / 进行中 / 已点亮 | P1 |
| FR-C3 | 错题本（旧识重温） | 错题按间隔重复排期，可组一局复习关卡重做 | P1 |
| FR-C4 | 复习提醒 | 今日有到期错题时给出页内提醒入口（**本轮不接微信订阅消息**） | P1 |
| FR-C5 | 勋章墙 | 18 枚勋章，含解锁状态与进度 | P1 |

**验收标准**

- FR-C1：柱状图最多 7 根（原型注释明确「只展示最近 7 天，避免移动端柱子过密不可读」）；无数据时为空态而非 0 值。
- FR-C2：`total = 0` 的领域必须是「未开始」，不得落进「进行中」；`mastery ≥ 90` 为「已点亮」（可对原型：AI 基础 92% 已点亮、RAG 80% 进行中、评测 0% 未开始）。
- FR-C3：答错 → 下次到期为 1 天后；复习答对 → 阶段推进、到期时间按 1/2/4/7/15/30 天递增；连续两次复习答对 → 移出队列。
- FR-C4：「今天先不复习」只影响当日首页提示，**不改变**错题的排期。
- FR-C5：未解锁勋章保留轮廓与名称并置灰（原型要求「让用户知道还有什么可以追求」）；解锁不重复写、不重复弹。

### 4.4 第 4 层 · 档案与设置（FR-D）

| 编号 | 需求 | 说明 | 优先级 |
|---|---|---|---|
| FR-D1 | 个人中心 | 身份卡片 + 等级进度 + 三宫格 + 三个入口计数 | P0 |
| FR-D2 | 冒险者卡片 | 可保存的公会卡（原型要求可长按保存） | P1 |
| FR-D3 | 头像与昵称 | 修改头像与昵称，刷新后保持 | P1 |
| FR-D4 | 设置 | 原型 07·5 的 8 个设置项全部可交互 | P1 |
| FR-D5 | 学习提醒设置 | 时间/星期/两个额外开关，保存后持久 | P1 |
| FR-D6 | 帮助与反馈 | 3 条 FAQ + 举报题目问题 + 联系开发者 | P1 |
| FR-D7 | 空态与异常 | 统一三态空态（无卷轴 / 无文档 / 断网），结构统一为「图标 + 一句解释 + 一个动作」 | P0 |

**验收标准**

- FR-D1：等级、进度、三宫格、入口计数全部来自接口；**接口异常时不显示错误数字**（宁可空态）。
- FR-D2：保存到相册成功或给出可理解的失败提示。
- FR-D3：头像上传后立即生效且跨设备可见（说明：不能只存临时路径）；昵称长度与内容合法。
- FR-D4：每个开关/入口都有明确行为；「清理缓存」显示真实占用并可清理；「账号与安全」显示绑定状态；版本号取自真实版本。
- FR-D5：保存后重新进入页面，选项保持用户选择。
- FR-D7：仅 07·7 一屏的三种空态抽为公共组件复用，页面内不重复实现。

## 6. 非功能需求

### 6.1 安全与隐私

| 编号 | 要求 |
|---|---|
| NFR-S1 | 用户身份凭证由服务端签发；客户端只持有凭证，**不持有任何可用于伪造身份的信息** |
| NFR-S2 | 所有需要身份的数据接口必须校验归属，按 id 读取时校验「这条数据属于当前用户」 |
| NFR-S3 | 登录态必须有明确有效期，且支持服务端主动失效 |
| NFR-S4 | 上传的头像必须做类型、大小与**真实内容**校验（不能只看扩展名），文件名由服务端生成 |
| NFR-S5 | 登录相关接口必须限流，防刷注册 |
| NFR-S6 | 只采集实现功能所必需的信息：**不采集手机号、不采集位置、不采集通讯录、不采集微信运动等** |
| NFR-S7 | 用户内容（昵称）需做长度与字符校验，拒绝空白/不可见字符 |
| NFR-S8 | 界面不出现任何内部机制说明（沿用既有红线） |

### 6.2 性能与容量

| 编号 | 要求 |
|---|---|
| NFR-P1 | 首次进入的登录建档不得阻塞首屏超过 3 秒 |
| NFR-P2 | 档案各页首屏数据来自单次聚合请求，不做 N+1 次往返 |
| NFR-P3 | 列表分页（默认 20 条），支持「已经到底了 · 共 N 份卷轴」的计数展示 |
| NFR-P4 | 数据量按单用户 3 年、每年 500 局估算，档案页响应仍应 < 500ms |

### 6.3 容错与可用性

| 编号 | 要求 |
|---|---|
| NFR-R1 | 报告生成失败**不得**导致答题记录丢失（原型 03·6 的硬要求） |
| NFR-R2 | 出题/结算/报告的失败都必须有可重试路径（重试不产生脏数据） |
| NFR-R3 | 付费能力之外的所有页面，在数据为空时展示空态而非报错 |
| NFR-R4 | 服务端不得因为「档案类数据缺失」而拒绝出题与答题——核心闭环优先 |

### 6.4 可维护性

| 编号 | 要求 |
|---|---|
| NFR-M1 | 后端延续 TDD；大模型与微信接口在测试中一律 mock |
| NFR-M2 | 数据库变更必须可回滚（每个迁移都提供回滚） |
| NFR-M3 | 算分规则在两处实现（前端即时反馈 + 服务端权威），必须由共享用例锁定一致 |
| NFR-M4 | 页面视觉与原型逐屏对齐，改动以原型为唯一依据 |

### 6.5 兼容性

| 编号 | 要求 |
|---|---|
| NFR-C1 | 小程序端与 H5 端都能跑通（H5 用于本机联调与快速验收） |
| NFR-C2 | 平台差异收敛到工具层单一分支，不在页面里散写环境判断 |
| NFR-C3 | 隐私授权相关能力在低版本基础库不拦截时仍需正常工作 |

## 9. 端到端验收标准

按顺序走通即视为本次交付通过：

1. 全新用户（清空本地数据）打开小程序 → 无弹窗进入大厅 → 个人中心显示默认昵称与默认头像。
2. 输入一段资料 → 召唤副本（三步进度）→ 题库确认 → 逐题作答（即时反馈）。
3. 交卷 → 结算页数字与服务端一致 → 个人中心 XP/等级/连续天数已更新。
4. 「查看冒险日志」→ 报告生成中 → 报告就绪 → 三句话总结、强弱项、三条建议齐全。
5. 个人中心 → 历史卷轴：能看到刚完成的这一局；点入详情可逐题回看。
6. 故意答错几题 → 错题本出现这些题 → 重新进入小程序时首页出现复习提示 → 组一局复习关卡并答对 → 错题阶段推进。
7. 知识树：答过的领域出现掌握度，`≥90` 显示已点亮，未答过的显示未开始。
8. 数据看板：7 根柱子、正确率趋势、平均用时、领域掌握度均来自真实数据。
9. 勋章墙：解锁数与实际行为一致；未解锁置灰但可见。
10. 设置：改开关 → 返回再进入仍保持；改头像与昵称 → 立即生效。
11. 越权验证：用 A 的登录态请求 B 的卷轴详情 → 被拒绝。
12. 报告生成失败场景：答题记录不丢，可重新生成。
